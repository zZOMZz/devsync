# 项目控制面板

## 启动与接入项目

本机需要 Node.js 22+。在源码仓库先执行 `npm ci`，然后在任意目录运行：

```bash
devsync dashboard
```

也可以直接使用源码入口：

```bash
node /path/to/devsync/bin/devsync.mjs dashboard
```

控制面板列出已登记的项目。旧项目首次使用时按 `a`，输入包含 `.sync/config.json` 的项目目录。此操作只登记路径，不开始同步。新版本执行 `init/config/sync/start` 成功后会自动登记。没有登记过的旧项目不会通过扫描整块磁盘自动发现。

默认用户索引位于 `~/.config/devsync/projects.json`，Linux/macOS 的 `XDG_CONFIG_HOME` 或 Windows 的 `APPDATA` 遵循现有用户配置位置规则。只保存名称和本地真实路径；密码、连接配置和运行状态仍属于各项目。符号链接形式的目录会解析并去重。

`dashboard --dir /path/to/project` 可以初始选中一个已登记项目，列表仍包含全部已登记项目。

## 操作

| 按键 | 行为 |
| --- | --- |
| ↑ / ↓ | 选择项目 |
| PageUp / PageDown | 按页选择 |
| Enter | 查看详情；在详情内再次 Enter 返回 |
| s | 开启所选项目的自动同步 |
| x | 停止所选项目的自动同步 |
| c | 修改所选项目配置，保存后保持暂停 |
| a | 添加已配置的项目目录 |
| l | 重新定位当前记录到另一个已配置目录 |
| d | 移除索引记录，默认不确认；不删除文件、不停止同步 |
| r | 立即刷新 |
| q / Ctrl+C | 退出面板 |

详情中用 ↑ / ↓ 滚动，Esc 返回列表。列表按已开启自动同步优先排列，刷新时保持当前项目选择。

开启时复用原来的 `start` 流程。需要首次确认或配置变化确认时，退出 Ink 界面并展示 Clack 差异预览，沿用项目备份策略；未确认不会开始新的同步。向导完成后回到面板。执行操作时不会同时接收第二个项目操作，其他终端的冲突由项目锁处理。

`l` 只更新索引，不移动目录，也不迁移 Mutagen 会话、IPC 或后台进程。新目录必须已配置；启动时仍会核对配置并按需重新确认。项目目录移动后的完整运行状态迁移尚未实现。

## 状态与退出

列表分开显示“自动同步管理”和“文件状态”。“已开启”不等于文件已经对齐；可能同时显示断连、扫描或错误。没有后台管理进程但会话仍启用时，显示“未托管”；目录消失时保留记录并显示“目录不可用”。

面板每约 3 秒刷新，最多同时查询 3 个项目，单项目总查询最多等待 12 秒。慢项目不会阻止其他行更新。查询过程不启动 daemon，也不访问远端来重新验证连接。

退出只结束面板和它的查询，不停止既有后台同步；若正在执行开启/配置操作，Ctrl+C 按原操作的中断规则清理。关闭后可以在项目目录运行 `devsync status` 确认状态。

## JSON 与非交互环境

```bash
devsync dashboard --json
```

返回 `ok`、`dashboardVersion: 1`、`registryError`、`loading` 和 `projects`。项目行包含 `root`、`name`、`target`、`updatedAt`，以及 `status` 或 `error`。`status` 使用版本化状态字段，省略原始 Mutagen `session` 数据。单项目异常保留在该行；索引整体读取失败时返回非零退出码及 `ok: false`。

JSON 查询不写索引、不开启同步，不输出终端控制字符。没有 TTY 或使用 `TERM=dumb` 时使用此入口；`NO_COLOR=1` 可关闭交互面板颜色。索引文件损坏时会显示错误并保留文件，修正后按 `r` 重试。

## 实现与范围

Clack 配置向导与 Ink 7 / React 19 控制面板共存，依赖及传递依赖随程序包分发，无需启动 Web 服务。Node.js 只要求安装在运行 CLI 的本机；远端仍使用 SSH 和 Mutagen agent。

本版按项目逐个操作，支持已知项目管理。全盘项目发现、批量开关、后台开机启动和目录移动后的状态迁移尚未实现。Mac 上已验证真实 PTY 与真实引擎操作；Windows/Linux 终端仍需实机验收。

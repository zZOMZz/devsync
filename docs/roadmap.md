# 优化候选与建议顺序

基线：0.1.0，2026-09-08。当前版本已通过实现阶段测试和用户验收反馈。本页是后续开发候选，不是已交付能力清单；具体范围由下一次任务确定。

## 第一批：明确接口并收敛异常路径

| 事项 | 当前依据 | 建议完成标准 |
| --- | --- | --- |
| 去掉配置流程的重复 SSH 验证 | 向导逐步验证后，服务保存前又验证一次 | 普通流程减少连接次数，API 调用方仍不能绕过必要验证；取消保留原配置 |
| 统一 JSON 与错误对象 | 部分异常仍用通用错误；`status` 返回底层 session 结构 | 定义稳定 DTO、错误码和版本策略，明确 `ok` 与运行健康度的区别，增加契约测试 |
| 统一 SSH 认证配置 | `remote.mjs` 识别私有配置的 `identityFile`，Mutagen 参数构造未对应传入 | 先复现显式 identityFile 场景，再让探测与传输使用一致的认证来源；兼容 SSH config |
| 配置保存的失败恢复 | 两个私有文件分别保存，只有部分失败回滚 | 用故障注入验证每一步失败后的配置、凭据、规则文件及旧会话状态 |
| 取消与退出清理 | 核心在关键节点检查 signal；CLI 另行取消子进程 | 定义 API 与 CLI 一致的取消语义，验证下载/备份/flush 中断后锁与进程状态 |

以上“当前依据”来自源码阅读。异常场景的具体触发方式、影响范围和修复方案仍需针对性复现，不将源码线索直接视为所有环境都会发生的故障。

## 第二批：补齐运行诊断和异常恢复

- 设计 `doctor` 或等价诊断入口：检查本机依赖、规则、缓存与后台状态；远端检查需明确何时连接。当前没有该命令。
- 增加可轮转的项目日志，记录状态变化和错误类别，不记录密码或环境文件内容。
- 验证断网、VPN 恢复、密码变化、电脑休眠、后台进程异常退出后的行为，避免用单次同步通过代替持续运行验收。
- 为损坏锁文件、恢复目录残留、PID 重用、安装中断和多进程同时停止等情形建立故障注入测试。现有 owner 存活检测不等于这些情形均已覆盖。
- 明确“管理进程已退出但 Mutagen 会话仍活跃”的状态展示和恢复路径。

完成标准：用户可以从状态输出确定当前是否在同步、为什么停止、下一步执行什么；日志和重试行为由可复现测试验证。

## 第三批：性能与升级

- 本地文件哈希、程序包和缓存文件哈希目前通过读取完整文件计算。先用大文件、大目录测量内存和耗时，再评估流式哈希与有限并发。
- 保持三处筛选规则一致后，再评估清单生成性能；避免为提速改变预览范围。
- 增加明确的 Mutagen 升级流程。当前缓存按版本隔离，但确认指纹不包含发行版本，daemon 版本迁移也没有完整设计。
- 设计缓存清理命令前先确认哪些项目/进程仍引用旧程序，避免清理活跃版本。当前没有缓存清理命令。
- POSIX 长路径现在通过报错处理；如改为更短的 IPC 路径或独立状态根目录，需要同时设计项目识别、迁移与清理规则。

完成标准：有变更前后可复现数据，旧项目仍可运行，升级/清理不影响其他项目。

## 第四批：分发与可选界面

- 补齐 Windows/Linux 客户端验收矩阵，包括路径、权限、OpenSSH、进程退出和缓存锁。
- 明确版本号、包名、发布渠道、更新策略和发行包验证流程。目前只支持本地分发，npm 包处于 private 状态。
- 基于稳定的 CLI/API 再实现 VS Code 界面，优先配置向导、状态栏和预览列表，复用已有后台进程。

多远端、双向同步、开机启动、更完整的 glob 语法以及远端非 Linux 支持都属于新范围。应分别明确需求与验收标准后再进入实现。

## 每个优化任务的最小记录

```text
目标：

复现步骤与证据：
本次范围：
预期行为：
涉及模块：
```
